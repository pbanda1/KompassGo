# Definition of Ready (DoR)

> A user story may enter a sprint only when **all** of the following are true.

| # | Criterion | What it means |
|---|-----------|---------------|
| 1 | **Written as a user story** | "As a …, I want …, so that …". A spike has a clear question it answers. |
| 2 | **Has acceptance criteria** | The criteria can be checked (yes / no). |
| 3 | **Estimated** | Estimated in story points and **not larger than 8 SP**. Larger stories are split. |
| 4 | **Prioritised** | Has a priority and belongs to an epic. |
| 5 | **Broken down** | Split into subtasks, each with an estimate in hours and a layer label (`frontend` / `backend`). |
| 6 | **No blocking dependencies** | Dependencies are resolved, or are in the same sprint and scheduled before it. |
| 7 | **Understood by the team** | The team understands it and there are no open questions. |

## Checklist (use at Sprint Planning)

- [ ] User story format (or a spike with a clear question)
- [ ] Verifiable acceptance criteria
- [ ] Estimated, max 8 SP
- [ ] Priority set, linked to an epic
- [ ] Subtasks with hours and layer
- [ ] Dependencies resolved
- [ ] No open questions
